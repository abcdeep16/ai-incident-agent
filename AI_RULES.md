# AI Assistant Rules

These rules apply to every AI assistant working in this repository.

## Required reading

1. Read this file, [AI_RULES.md](./AI_RULES.md), first.
2. Read [README.md](./README.md).
3. Read the relevant documents before acting:
   - [PROJECT_CONTEXT.md](./PROJECT_CONTEXT.md)
   - [ARCHITECTURE.md](./ARCHITECTURE.md)
   - [DATABASE_SCHEMA.md](./DATABASE_SCHEMA.md) for database work
   - [API_DOCUMENTATION.md](./API_DOCUMENTATION.md) for API work
   - [KNOWN_ISSUES.md](./KNOWN_ISSUES.md) for known limitations
   - [DECISIONS.md](./DECISIONS.md) for design history
   - [CHANGELOG.md](./CHANGELOG.md) for recorded changes

## Rules

- Never invent files, functions, APIs, schema fields, configuration, behavior,
  tests, or product capabilities.
- Do not treat prose documentation, previous conversation, generated artifacts,
  or a successful smoke test as proof that unrelated behavior is implemented.
  Verify the relevant implementation.
- When a claim is not verified, label it explicitly as **Unknown** or
  **Unverified**. Clearly distinguish facts, assumptions, and unknowns.
- If documentation conflicts with the code, inspect the current code, report
  the discrepancy, and update the affected documentation when the change is in
  scope.
- Before modifying code, inspect the relevant implementation and its callers,
  tests, configuration, and data flow. Do not overwrite or remove existing
  behavior without understanding its purpose.
- Make the smallest complete change that addresses the request. Avoid unrelated
  refactors and do not revert other work in the working tree.
- Ask for clarification when a required behavior or scope has multiple
  materially different interpretations. Do not silently choose a consequential
  design.
- Keep all affected documentation synchronized with code, configuration,
  database, and API changes.
- Run the smallest relevant existing build, lint, or test command. Report what
  was run and its actual outcome; do not claim tests passed if they were not run.
- Do not claim a feature is implemented unless the current implementation has
  been verified.
- Do not commit credentials, private data, or other secrets. Respect
  `.gitignore`; do not overwrite model artifacts or datasets unless the task
  explicitly requires it.
- The incident output is not generated by a remote LLM in the current
  implementation. Describe the trained classifier, local evidence retrieval,
  and template-generated narrative accurately; do not describe it as
  generative AI.

## Reporting

When providing a result, summarize the verified change, list relevant
validation, and call out unresolved limitations. Do not hide uncertainty behind
confident language.
