# Known Issues and Limitations

This list reflects issues verified by source inspection or a recent local
runtime check. Re-check before relying on it; status can change.

## Persistence and history depend on PostgreSQL

- **Impact:** When `DATABASE_URL` is unset or PostgreSQL is unavailable,
  history requests fail and investigations are not saved.
- **Verified behavior:** Investigation can still return analysis with a
  persistence warning; `GET /api/incidents` returns HTTP 500.
- **Workaround:** Configure a reachable PostgreSQL database and valid
  `DATABASE_URL`. `DATABASE_SSL=false` disables SSL if appropriate for the
  environment.
- **Code/documentation discrepancy:** The backend startup log says both
  investigation and history will fail until the database is fixed. The
  investigation handler actually catches insert failures and returns the
  analysis with a warning. The log text is therefore broader than the actual
  handler behavior.

## The analysis is not a generative LLM investigation

- **Impact:** Root-cause wording and recommendations are generic templates,
  not reasoning generated by a conversational AI. Do not interpret them as a
  confirmed diagnosis.
- **Verified behavior:** The TF-IDF + Logistic Regression classifier selects
  anomaly/normal templates. Evidence is separately retrieved from local files.
- **Workaround:** Treat results as a prototype signal and verify against
  operational telemetry and logs.

## Heuristic training labels and metrics

- **Impact:** Training labels are produced from keyword substring matches,
  not ground-truth annotations. The metrics evaluate agreement with those
  heuristic labels on a random split, not real incident detection quality.
- **Workaround:** Use reviewed, independently labeled data and an evaluation
  design that prevents data leakage before making quality claims.

## Model artifact required for prediction

- **Impact:** `local_model_service.py` raises `FileNotFoundError` if
  `ai-service/artifacts/log_anomaly_pipeline.joblib` is missing.
- **Workaround:** Install Python dependencies and run
  `python train_local_model.py` from `ai-service/`, or restore a compatible
  artifact.
- **Additional note:** The health endpoint does not load the artifact, so a
  healthy response alone does not establish that inference will succeed.

## Embedding-model availability

- **Impact:** Evidence retrieval loads `all-MiniLM-L6-v2` through
  Sentence Transformers. If it is not cached, the library may need to fetch
  the model. Offline first-run behavior has not been verified.
- **Workaround:** Ensure the embedding model is available to Sentence
  Transformers in the runtime environment before testing evidence retrieval.

## Limited local evidence set

- **Impact:** Evidence is read only from `data/logs/{service}.log`,
  `data/metrics/{service}.json`, and
  `data/deployments/{service}.json`. The inspected working tree contains sample
  evidence for `payment-service`; other service names can have no candidates.
- **Behavior:** If no files exist, retrieval returns an empty list and the
  analysis service falls back to prompt-derived evidence.
- **Workaround:** Add correctly named service data files in the expected
  directories.

## No backend automated test suite

- **Impact:** `backend/package.json` defines `npm test` as a command that
  prints “Error: no test specified” and exits with failure.
- **Workaround:** Use endpoint smoke tests and add an automated suite before
  relying on regression coverage.

## CORS configuration differs between services

- **Impact:** The backend explicitly allows local `localhost` and
  `127.0.0.1` development origins. The AI service's own allowlist only adds
  `localhost` development origins by default.
- **Current path:** The browser calls the backend, and the backend calls the
  AI service server-to-server, so browser CORS to the AI service is not
  required for the current UI flow.
- **Workaround:** If a browser client is added that calls the AI service
  directly, configure its allowed origin explicitly.
